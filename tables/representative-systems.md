# Representative Systems

This table extends the paper's representative-systems table from 6 to 48 systems. Archetypes C1
through C6 contribute 6, 6, 13, 6, 8, and 9 systems, respectively. They were selected to span the sub-groups of each archetype and,
within C3, its in-process evaluation modes. Selection emphasizes structural variety and deployment evidence rather
than proportional sampling of the 317 archetype studies.

Rows summarize the cited studies' reported evaluation settings and results, including workloads, budgets, and
baselines where available. Quantitative results retain their stated reference points; limitations and missing
comparisons are identified where relevant. Results in different rows were obtained under different
systems, workloads, budgets, and baselines, and are therefore not comparable across rows.

| **C1 — Auxiliary intelligence for conventional control** | | | | |
| COMET [1] | incident triage on two Microsoft cloud services | keywords extracted from filtered incident logs, per incident | fine-tuned FastText embedding and Faiss retrieval rank teams; recommendation posted to the incident page; no reported in-process check on the model output | engineers decide and act; online top-1 accuracy 0.61 vs. 0.47 for the rule-based router, time to mitigation −35% before vs. after (>6 months deployed) |
| Liu et al. [2] | cardinality estimation in PostgreSQL | per-sub-query estimate from a fine-tuned Llama-3 8B, prompted with statistics and other estimators' outputs | re-estimation when far from a reference estimator; PostgreSQL optimizer chooses the plan | optimizer acts (testbed); 99th-percentile Q-error 30.90 vs. 119 for ALECE on STATS; selective variant has the lowest end-to-end time; pre-fine-tuned variant slower than PRICE on two workloads once inference is counted |
| HCAO [3] | UAV-relayed edge task offloading | semantic summary of global state every 20 slots from a DeepSeek API model | Maxvar-DDQN ensemble selects offloading actions; no reported in-process check on the model output | RL agents act (simulation); completion time 120.74 vs. 131.76 frames and deadline violations 1,962 vs. 3,826 against raw global state |
| IAN [4] | bandwidth allocation from intents | QoS weight vector per service | DuelingDQN allocates bandwidth with the weights in its state; no reported in-process check on the model output | DRL acts (simulation); QoS revenue +27.99% vs. next-best DRL at 80 services; model-only allocation worse |
| FM agentic slicing [5] | RAN slice partitioning for XR and eMBB | reward weights from telemetry and intent, event-triggered | deterministic validator, ≤3 retries, fallback to last valid weights; DDPG partitions, scheduler allocates per TTI | controllers act (simulation); XR queue drains after intervention vs. diverging under static WRR; simulation assumes a 10 s model delay |
| FLARE [6] | reliable multi-hop edge offloading | validity-checked action cues during MAPPO training, annealed to zero | MAPPO policy selects every action; deployed policy makes no model call | DRL acts (simulation, 10-device Jetson testbed); 60.33% task success vs. 54.55% MAPPO and 56.12–56.16% with heuristic cues (10 nodes) |

| GPTuner [7] | DBMS knob tuning (PostgreSQL, MySQL) | knob selection and value ranges from manuals, forums and the model's knowledge, once per DBMS | coarse-to-fine SMAC Bayesian optimization selects; stress-test measurement; region discard of crash-prone ranges | tuning harness acts on a DBMS copy (testbed); TPC-H latency −44.4% vs. default within 20 iterations; $23.7 knowledge cost for 150 knobs |
| AutoSizer [8] | analog/mixed-signal transistor sizing | variable and range selection, optimizer choice, revision from optimization history | BO, GA, LHS or SA propose sizes; Ngspice (SKY130) checks specifications | no consequential action (simulation); all specifications met in 100% of hard-circuit trials vs. 25–80% for baselines |
| ADO-LLM [9] | analog sizing (90 nm) | 5 initial points and 1 of 5 proposals per iteration, from top-FOM examples | GP-BO proposes the other 4; HSPICE simulates every point; format and range parser | no consequential action (simulation, single runs); amplifier FOM 3.52, all specs met, vs. 1.89 (GP-BO, equal budget) and 2.10 (4× budget) |
| LEMOE [10] | RISC-V BOOM microarchitecture exploration | program-aware initial designs, candidate sampling, surrogate prediction of IPC and power | EHVI acquisition selects; Chipyard/VLSI flow evaluates each chosen design | no consequential action (EDA flow, no repeated runs); hypervolume 0.895 vs. 0.814 for BOOM-Explorer with 15 evaluations |
| ReasoningCompiler [11] | TVM tensor-program scheduling | next transformation from TVM's legal set at each MCTS expansion | UCT and TVM cost model select; invalid proposals filtered, non-model fallback | no consequential action (5 CPU platforms); geomean 5.0× vs. 2.7× for TVM evolutionary search with 5.8× fewer samples; lead closes at large budgets |
| QiMeng-Tensify [12] | GPU tensor-graph scheduling | probability prior over seven schedule rules at each MCTS node; prompt evolved offline from measurements | MCTS with measured reward; numerical check against a reference zeroes failing kernels | no consequential action (A100, H100); 1.31× vs. re-implemented Reasoning Compiler and 2.86× vs. TensorRT on A100 FP16 subgraphs |
| **C3 — Candidate synthesis** | | | | |
| CUDA-L1 [13] | faster CUDA implementations of KernelBench PyTorch workloads | DeepSeek-V3-based model writes the full implementation; trained by SFT and contrastive RL on measured speedup | single-pass at evaluation; training reward from 1,000-input correctness test and paired timing, harness patched after reward hacking | no consequential action (benchmark); mean 3.12× (median 1.42×) over the default reference on A100, 249/250 tasks correct, same tasks as training |
| LLM-QO [14] | join order and operators for PostgreSQL queries | fine-tuned LLaMA-3-8B emits one plan per query; SFT and DPO on measured execution times | single-pass: plan forced through pg_hint_plan, no validator or fallback | PostgreSQL executes the plan (testbed); DSB mean execution time 31.3% of PostgreSQL's, Bao 3.09 s vs. 3.02 s |
| lambda-Tune [15] | PostgreSQL and MySQL knobs and indexes for OLAP workloads | GPT-4 writes five complete tuning scripts from a token-budgeted workload summary | sample-and-select: workload executed under each configuration with geometrically increasing timeouts; fastest kept | tuner applies configurations (testbed); relative cost 1.41 vs. 1.82 DB-BERT, 1.91 GPTuner, 2.00 UDO over 16 scenarios |
| ReSequel [16] | SQL query rewriting across workloads | Gemini-2.5-pro or OSS-120B rewrites query templates into several variants | sample-and-select: result equality on downsampled databases, then Top-1 by sample runtime; original query always kept; no formal proof | submitted to the host DBMS without human approval (testbed); JOB 5.64× over PostgreSQL, 6.18× over LearnedRewrite |
| VerilogCoder [17] | Verilog from specifications | GPT-4 Turbo or Llama3-70B agents plan sub-tasks, write and debug code | check-gated: iverilog syntax check, then testbench simulation with AST-based waveform tracing until the testbench passes; the golden testbench is also the scoring oracle | no consequential action; 94.2% on VerilogEval-Human v2 vs. 60.3% for non-agentic GPT-4 Turbo |
| ECO [18] | performance anti-patterns in Google's C++ fleet code | fine-tuned Gemini Pro 1.0 writes the edit and fixes build/test failures | check-gated: CI build and tests, LLM repair and self-review, then code-owner review; profiler monitoring with revert | human code owners approve, release pipeline deploys; >6.4k commits, >2M normalized cores saved, revert rate 0.12–0.16%; reviewers rejected 23–47% |
| GenRewrite [19] | faster equivalent SQL for PostgreSQL | o3-mini rewrites queries using retrieved natural-language rewrite rules | measurement-driven: counterexample and syntax repair, SQLSolver or SlabCity correctness gate (formal verification or execution testing), shadow execution ≥1.2× | rewrites left to the user; TPC-DS 25 queries ≥2× vs. 18 plain LLM, 10 LLM-R2; SQLSolver certifies 18.9% of TPC-DS rewrites |
| Astra [20] | CUDA kernels taken from the SGLang serving stack | four agents split test generation, profiling, planning and code rewriting over five rounds | measurement-driven: tests derived from the baseline kernel check equivalence and profiling times each round; the role split exists to keep the measurement signal trustworthy | no consequential action (H100); three kernels 1.26–1.46× (mean 1.32×) over the SGLang baseline vs. 1.08× for one agent doing everything, which produced a 0.73× slowdown on the most complex kernel from unrepresentative test inputs |
| STELLAR [21] | Lustre parameters for HPC applications | a GPT-4o agent analyses Darshan logs and a Claude-3.7-Sonnet agent proposes configurations; reflection writes reusable rules | measurement-driven: application runs measured, ≤5 configurations, best kept; RAG-derived valid ranges | runner applies parameters on a CloudLab testbed, no per-change approval; up to 7.8× over default, similar to a human expert on most workloads |
| Autocomp [22] | tensor-accelerator kernels (Gemmini, Trainium, L40S) | LLM ensemble plans one optimization from a menu, then rewrites the code | search-managed: beam search (B=6), functional tests vs. reference, keep only correct candidates faster than their parent | not deployed; Gemmini GEMM 1.4× geomean over hand-optimized Exo, Trainium 1.36× over hand-optimized NKI |
| KernelBand [23] | Triton kernels for 183 benchmark tasks | DeepSeek-V3.2 rewrites a selected kernel under a selected optimization strategy | search-managed: a bandit picks the (kernel cluster, strategy) pair and profiler signatures mask strategies whose target resource is already saturated; correctness and measured latency score every candidate | no consequential action (A100, RTX 4090, H20); geomean 1.91× on A100 vs. 1.34× for GEAK and 0.98× for best-of-N; giving the strategy choice to the model instead of the bandit reduces the geomean from 1.57× to 0.97× in the ablation experiment |
| KernelEvolve [24] | Triton kernels for ranking and recommendation operators | retrieval-augmented agent proposes candidate kernels | search-managed: graph search selects on measured speedup, with a tolerance-based comparison against the PyTorch reference on generated inputs | selected kernels run in Meta's production infrastructure, with no fleet-level impact figure; conv1d at the production shape (FP16, H100) 2.30× over PyTorch conv1d and 1.62× over a cuDNN conv2d workaround; out-of-distribution shapes regress to 0.39–0.63× |
| RTLRewriter [25] | RTL rewriting for smaller, faster logic | GPT-4V analyses code and diagram and rewrites sub-circuits | search-managed: cost-aware MCTS; fuzzing, then SAT (ABC) or e-graph (egg) equivalence, then synthesis | no consequential action; wires/cells 0.69/0.77 of Yosys vs. 0.85/0.87 for GPT-4 on the short benchmark |

| **C5 — Advisory diagnosis and management** | | | | |
| AIDA [33] | Root cause of multi-vendor network-device failures | Fine-tuned Qwen2.5-7B mines causal chains from vendor emails offline; online LLM validates evidence nodes against filtered logs | Knowledge-graph candidates, log-template filtering, scoring rule selects the root cause; abstains when no chain validates | Operators and vendors repair; production precision 95.4% (75.3% on unseen cases); median time to root cause 1.6 min vs. 72.6 h for the manual process, before vs. after with no control |
| BiAn [34] | Localization of failing devices in a cloud network | Hierarchical agents summarize alerts and rank candidate devices with explanations | Fixed three-pipeline workflow; device ranks averaged over three runs; no non-model ranking check | Operators act; top-1 accuracy 95.5% on 357 real incidents vs. 86.3% for the production rule system; over 10 months of deployment an A/B test against manual investigation reported 20.5% shorter time to root cause |

| GALA+ [38] | Root cause of microservice incidents | One investigator agent per candidate pod reasons over native metric, log and trace evidence; further agents synthesize and consolidate the ranking | Two non-model rankers seed the hypotheses; confidence-gated expansion over the trace dependency graph; no reported independent check on the final ranking | No action taken (fault-injection benchmarks); top-1 accuracy 74.44% on OnlineBoutique vs. 66.67% for the best non-model baseline and 48.35% for the best language-model baseline; replacing either adjudicating agent with a rule costs about 11 points |
| CausalDX [39] | Long-tail and cascading big-data platform incidents | GPT-4 agents grow and prune a causal graph over rule-detected anomalies and propose mitigations | Tool-grounded verification; acceptance threshold with a model-estimated likelihood; up to three retries | Incident owners execute under a human-gated protocol; precision 73.2% vs. 24.1% for the production rule system on 287 incidents; rated useful in 74% of 118 responses vs. 61% |
| Andromeda [40] | DBMS configuration debugging | LLM selects knobs and values from a user question, retrieved manuals and past answers, and anomalous telemetry | Retrieval and telemetry analysis assemble evidence; no reported in-process check on the answer | User or DBA applies; 79% of 100 MySQL cases (70 reproduced real questions, 30 designed) resolved as judged by experts vs. at most 57% for baseline configurations |

| TuxBot [44] | Linux kernel and sysctl parameter tuning under load | Gemini 2.5 Flash-Lite (instant loop) and Flash (reasoning loop) emit typed knob values at different cadences from application and system telemetry | Parameter validator checks type, range, domain and scope and rejects proposals outside the active knob set; failed writes leave the previous configuration in place; no human approval required in the evaluated loop | Machine, writing to a running bare-metal host under a live benchmark workload; the only evaluated method with a positive geometric mean over defaults after convergence (+72.5% vs. −31.9% for the MLOS tuner) across 13 workloads; the validator is not ablated |
| KubeIntellect [45] | Natural-language Kubernetes cluster operations | GPT-4o supervisor routes a query to domain agents that call read, write, delete and exec tools; a code-generator agent writes a new tool when none matches | Generated tools run in an in-process REPL under a 30-s timeout, pass AST, whitelist and schema checks, and need operator approval before registration (63 of 77 admitted, 14 failed after up to three attempts); cluster mutations pass through RBAC and require operator confirmation, with a dry-run diff before manifests are applied | Machine, on a live cluster of 170 pods and 18 namespaces; 200 queries, with every query outside tool synthesis returning a valid response and 118 responses raising clarification or approval; on 16 injected-fault scenarios, 75% pass versus 50% for a tool-less GPT-4o baseline |
| Agoran [46] | RAN slice resource allocation from stakeholder intents | LLM broker agents structure intents and negotiate a choice among optimizer offers | NSGA-II supplies only feasible Pareto offers; rule-based trust score before broadcast | Machine, via a RIC xApp on an OpenAirInterface testbed; one scripted scenario; 8.3% net PRB saving vs. a static configuration |
| ARM [47] | SLA-violation remediation on a cloud–edge cluster | GPT-5 ReAct agent diagnoses and issues scale, patch, apply and delete commands through MCP tools | Typed tools and duplicate-call filter; completion judged by the agent; no reported pre-execution acceptance gate | Machine, on a k3s testbed with 60 injected faults; GPT-5 mitigation success 80%, 90%, and 80% across three applications (Table V); abstract reports 70.7%; no conventional baseline |
| ChaosEater [48] | Chaos engineering and resilience repair for Kubernetes | GPT-4o agents write steady-state tests, fault plans and reconfigured manifests | Manifests applied first, then tested under injected faults with model-written tests; iterate on failure | Machine, on a development cluster; planted weakness repaired in 9 of 10 runs; $0.21–0.84 per cycle |
| Agentic DTN [49] | Digital-twin network remediation (MEC migration, slicing) | LLM agents plan, write the twin application and its tests, and write the actuation script | Sandbox compile, test and KPI check before actuation; bounded correction cycles; rollback and escalation on failure | Machine, on an emulated network; success 100% to 53.3% across four models (30 runs each); +16.7 to +80.0 points over first-attempt success |
